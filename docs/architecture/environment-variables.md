# Environment Variables

Copy `.env.example` to `.env.local`. Values are placeholders only. Static UI
startup needs no Supabase configuration.

| Variable                        | Exposure                     | Required when              | Purpose                                                                         |
| ------------------------------- | ---------------------------- | -------------------------- | ------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SUPABASE_URL`      | Browser-safe                 | Creating a Supabase client | Folioone Supabase project endpoint.                                             |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Browser-safe publishable key | Creating a Supabase client | Identifies the project client; database access remains subject to Auth and RLS. |

| `PERSONA_STORAGE` | Server-only | Optional | `fixture` (default, in-memory) or `supabase`. Choose `supabase` only after the M3C SQL, **including `004`**, has been approved, executed and verified (until `004`, a stale version hangs through PostgREST); see [Milestone 3C](milestone-3c-persona-persistence.md). Never prefix with `NEXT_PUBLIC_`. |
| `RAZORPAY_KEY_ID` | Server-only (sent to the browser only to open Checkout) | Optional | Razorpay key id (`rzp_test_…` / `rzp_live_…`). With the two below, enables PRO upgrades; unset shows "Payments coming soon". |
| `RAZORPAY_KEY_SECRET` | Server-only | With `RAZORPAY_KEY_ID` | Creates orders and verifies payments with Razorpay. Never prefix with `NEXT_PUBLIC_`. |
| `FOLIOONE_ENTITLEMENT_SECRET` | Server-only | With `RAZORPAY_KEY_ID` | 64 hex characters generated by `docs/sql/milestone-9/002-billing-secret.sql`; must equal the value stored in `folioone.billing_secrets`. Signs the proof `billing_activate_pro` checks (AD-011). Not the Razorpay secret. Never prefix with `NEXT_PUBLIC_`. |
| `GEMINI_API_KEY` | Server-only | Gemini provider only | Enables legacy Gemini resume import when no provider override exists, or when `AI_PROVIDER=gemini`. Never prefix with `NEXT_PUBLIC_`. |

## LLM provider configuration

Use the same server-only names for Google, OpenAI, or a local gateway. Lowercase
`llm_*` takes precedence over uppercase `LLM_*`, then provider-specific legacy
settings. Never use `NEXT_PUBLIC_` for these settings.

| Setting               | Meaning                                                                                                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `llm_provider`        | `google`, `openai`, or `local`. Legacy aliases `gemini` and `openai-compatible` remain accepted.                                                                                            |
| `llm_endpoint`        | API base prefix; not a complete completion URL. Defaults: Google `https://generativelanguage.googleapis.com/v1beta`, OpenAI `https://api.openai.com/v1`, local `http://127.0.0.1:31415/v1`. |
| `llm_model`           | Local defaults to `auto`; Google retains the existing `gemini-3.5-flash-lite` default. OpenAI requires an explicit available model ID.                                                      |
| `llm_api_key`         | Server credential; required for Google/OpenAI, optional only for local gateways that permit unauthenticated requests.                                                                       |
| `llm_response_format` | `json_schema` (default) or `json_object` for OpenAI-compatible transports. Local schema validation always applies.                                                                          |

Local example for `.env.local` (set secrets securely, never commit them):

```dotenv
llm_provider=local
llm_endpoint=http://127.0.0.1:31415/v1
llm_model=auto
# llm_api_key=your-gateway-key
```

The existing `AI_API_KEY` still works for local; copying the key is unnecessary.
For Google select `llm_provider=google` and provide `llm_api_key` or `GEMINI_API_KEY`.
For OpenAI select `llm_provider=openai`, set `llm_model`, and provide `llm_api_key`
or `OPENAI_API_KEY`. A generic `llm_api_key` is deliberately used with whichever
provider you select; keep its value consistent with that selection.

Without a preferred provider, `AI_PROVIDER` is honored; otherwise Google is the
default and an existing Gemini key preserves legacy behavior. `AI_BASE_URL`,
`AI_MODEL`, and `AI_API_KEY` are used only for local. Cloud selection never reuses
those legacy local settings. `AI_RESPONSE_FORMAT` remains a format fallback.
Missing cloud credentials disable import; invalid settings send no requests.

This checkout's ignored `.env.development.local` contains the earlier legacy
local gateway settings. Preferred `llm_*` values from `.env.local` override those
legacy names in application configuration. Next.js still resolves duplicate
variables of the same name using its normal env-file precedence. Restart
`pnpm dev` after edits. Containers need a reachable endpoint: `127.0.0.1` means
the container itself. Configuration and credentials remain server-only.

Google uses native generateContent and `x-goog-api-key`; OpenAI/local use Chat
Completions and bearer auth. Derived Responses, Messages and Embeddings URLs
remain available for future consumers; this does not add new product features.
Current integration is authenticated resume import. PDF inputs and schema mode
need selected-model support. Requests are uncached with a two-minute timeout and
never silently retry another provider. Existing resume validation and merge
behavior are unchanged (product decision D-003).

The local gateway passed six synthetic authenticated checks on 2026-11-15; see
[curl examples and results](ai-gateway-smoke.md). Google/OpenAI switching is
mock-tested only; no cloud request or real resume is part of these changes.

Protocol references: [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create),
[file inputs](https://developers.openai.com/api/docs/guides/file-inputs), and
[structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

The application has no PostgreSQL connection string and no service-role key.
The server verifies the cookie-backed Supabase session with `auth.getUser()`;
user-owned PostgREST requests then use that authenticated client. The user's
JWT, not a browser-supplied user ID, supplies `auth.uid()` for RLS.

The optional authenticated Playwright integration flow reads
`FOLIOONE_DEV_TEST_EMAIL` and `FOLIOONE_DEV_TEST_PASSWORD` from the test runner
process only. Configure them only for a dedicated, confirmed development test
account in a local secret manager or CI secret store. They are not application
variables, must never use a `NEXT_PUBLIC_` prefix, and must not be committed.
The test restores the original profile headline before signing out. Without
these values, the authenticated hosted flow is skipped; the unauthenticated
route check can still run.

The developer's administrative `postgres` connection is used only in Supabase
SQL Editor for manually executing reviewed DDL. It is not an application
variable, must not be added to `.env.local`, deployment settings, browser code,
or tests, and is never used for user-facing queries. Drizzle Kit configuration
contains no database credentials and does not execute migrations.

Never define `SUPABASE_SERVICE_ROLE_KEY`, `DATABASE_URL`, or
`MIGRATION_DATABASE_URL` for application runtime. The service-role key bypasses
RLS; the administrative connection bypasses RLS as well.

## Environments

The database schema is **`folioone` in every environment**; it is a constant in `src/lib/db-schema.ts`, not a variable. Environments differ only by the Supabase project (URL + anon key) and `PERSONA_STORAGE`:

| Environment              | `NEXT_PUBLIC_SUPABASE_URL` / `_ANON_KEY`                                                                              | `PERSONA_STORAGE`                 | Where set                                              | Schema     |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------- | --------------------------------- | ------------------------------------------------------ | ---------- |
| Local development        | local stack (`pnpm supabase:local:start`; `http://127.0.0.1:54321`, key from `supabase status`) or none for static UI | `fixture` (default) or `supabase` | `.env.local`                                           | `folioone` |
| Local validation         | local stack, set by `pnpm validate` itself                                                                            | `supabase`                        | orchestrator process environment                       | `folioone` |
| Hosted staging (Railway) | the existing hosted Supabase project                                                                                  | `supabase`                        | Railway variables (`NEXT_PUBLIC_*` also at build time) | `folioone` |
| Production (future)      | a **separate** Supabase project                                                                                       | `supabase`                        | production service variables                           | `folioone` |

Rules: no service-role key or database URL anywhere; do not add `NEXT_PUBLIC_*` or other variables for the schema (a configurable name could silently point a deployment at `public`); it is not a Storage bucket name; never reuse a project's keys in another environment. Template: `.env.example`.

Post-deployment smoke tests read only `SMOKE_BASE_URL` and `SMOKE_USER_A_/B_EMAIL|PASSWORD` from the process environment ([staging-smoke-tests.md](staging-smoke-tests.md)); these are test-runner variables, never application variables.

## Local validation

`pnpm validate` builds its own environment (local Supabase URL and anon key from `supabase status`; random test-user passwords). It removes inherited `FOLIOONE_*`, `SUPABASE_*`, `NEXT_PUBLIC_SUPABASE*`, `PERSONA_STORAGE` and `DATABASE_URL` values, and refuses any non-loopback Supabase address. `FOLIOONE_VALIDATE=1` is set only by that workflow and is required by `vitest.local.config.ts` and `playwright.local.config.ts`. See [local-validation.md](local-validation.md).
